# STRIDE Threat Model - PhishGuard

Generated: 2026-05-10

## Architecture Components
- GUI Client (Tkinter)
- Authentication Module (bcrypt + TOTP)
- Analysis Engine (heuristic + optional ML)
- SQLite Data Store
- Report Export Service
- Security Audit Logger

## Trust Boundaries
1. User input boundary between GUI and analysis engine
2. Credential boundary between UI and authentication logic
3. Storage boundary between app logic and SQLite database
4. External URL boundary for untrusted links in emails

## STRIDE Analysis

| Threat | Scenario | Impact | Mitigation |
|---|---|---|---|
| Spoofing | Attacker attempts fake user login | Unauthorized access | bcrypt password hashing, TOTP verification, account activity logs |
| Tampering | User modifies scan outputs | Integrity loss in reports | Signed audit trail and immutable event logs in DB |
| Repudiation | User denies suspicious scan actions | Investigation gaps | Timestamped security events with user identity |
| Information Disclosure | Secrets leaked from storage | Credential compromise | Encrypted TOTP secrets and least-privilege role controls |
| Denial of Service | Oversized input payloads | App instability | Input size limits and validation policies |
| Elevation of Privilege | Standard user accesses admin logs | Privilege abuse | RBAC checks in UI and event-view gating |

## High-Risk Scenarios
- Credential theft via phishing email links
- Brand impersonation using lookalike domains
- MFA bypass attempts through brute-force OTP guessing

## Residual Risk
- Offline model may produce false positives/negatives
- External domain reputation APIs are not integrated in this demo build
